# Test Suite Organization

## Overview

This directory contains 265+ end-to-end tests organized by test strategy and purpose.

## Test Categories

| Category | Directory | Purpose | Priority |
|----------|-----------|---------|----------|
| **Smoke** | `smoke/` | Core functionality sanity checks | P0 |
| **Critical** | `smoke/` | Must-pass for any release | P0 |
| **Integration** | `integration/` | Multi-page user journeys | P0 |
| **User Types** | `user-types.spec.ts` | All 6 user type variations | P0 |
| **Login** | `login/` | Authentication flows | P1 |
| **Cart** | `cart/` | Cart operations | P1 |
| **Checkout** | `checkout/` | Checkout flow | P1 |
| **Product** | `product/` | Product listing/detail | P1 |
| **Pricing** | `pricing/` | Price display accuracy | P1 |
| **Security** | `security/` | Auth & session security | P1 |
| **Performance** | `performance/` | Load & response times | P1 |
| **Exception** | `exception/` | Error handling | P1 |
| **Negative** | `negative/` | Invalid input validation | P2 |
| **Boundary** | `boundary/` | Edge value testing | P2 |
| **Corner** | `corner/` | Extreme combinations | P2 |
| **Bug Verification** | `bug-verification/` | Known bug regression | P2 |

## User Types Coverage

All tests run against these 6 user types from `test-data/supported-users.ts`:

- `standard_user` - Normal happy path
- `locked_out_user` - Blocked user handling
- `problem_user` - UI rendering issues
- `error_user` - Error state rendering
- `visual_user` - Visual bug verification
- `performance_glitch_user` - Slow response handling

## Running Tests

```bash
# All tests (Chromium only)
pnpm test

# Smoke tests only
pnpm test --grep "@smoke"

# Critical tests only
pnpm test --grep "@critical"

# By category
pnpm test tests/smoke/
pnpm test tests/integration/
pnpm test tests/login/

# By tag
pnpm test --grep="@security"
pnpm test --grep="@performance"

# Parallel execution
pnpm test --workers=4

# With retry (CI)
CI=true pnpm test
```

## Test File Naming Convention

```
tests/
├── {category}/           # One directory per test category
│   └── *.spec.ts        # All test specs in lowercase with dashes
├── {feature}.spec.ts   # Only for top-level feature specs (root level)
└── helpers/             # Test-specific helpers (not global)
```

## Category Definitions

### Boundary vs Corner vs Negative vs Exception

- **Boundary** (`boundary/`) - Tests at limits of input ranges (min, max, empty, overflow)
- **Corner** (`corner/`) - Tests with extreme/unusual combinations of multiple conditions
- **Negative** (`negative/`) - Tests with invalid inputs, wrong data types, malformed input
- **Exception** (`exception/`) - Tests for error states, error messages, error recovery

### Smoke vs Integration vs User Types

- **Smoke** (`smoke/`) - Single-page sanity checks, fast feedback
- **Integration** (`integration/`) - Multi-page workflows, end-to-end journeys
- **User Types** (`user-types.spec.ts`) - Tests that must pass for ALL 6 user types

## Tags

| Tag | Purpose |
|-----|---------|

| `@performance` | Performance-sensitive tests |
